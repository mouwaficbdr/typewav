## Problème 1 — Texte UI hardcodé en français dans TypingArea

### Situation actuelle

`apps/web/components/typing/TypingArea.tsx` contient :

```tsx
{
  !isComplete && (
    <p
      className="absolute bottom-2 right-4 text-xs"
      style={{ color: 'var(--color-text-muted)' }}
    >
      cliquer pour activer · chaque frappe produit une note
    </p>
  );
}
```

Ce texte est **hardcodé en français** dans un composant utilisé dans les locales FR et EN.

### Fix

Utiliser `useTranslations('typing')` et les clés `typing.hint`.

## Problème 2 — `focus:outline-none` sans remplacement accessible

### Situation actuelle

`TypingArea.tsx` :

```tsx
<div
  ...
  className="relative cursor-text select-none rounded-md p-8 focus:outline-none w-full"
>
```

`focus:outline-none` supprime l'indicateur de focus par défaut du navigateur sans le remplacer. Un utilisateur naviguant au clavier (tabulation) ou avec des aides technologiques n'a aucun feedback visuel que la zone de frappe est active.

**WCAG 2.1 — 2.4.11 Focus Appearance (AA)** : L'indicateur de focus doit être visible.

### Fix

Remplacer `focus:outline-none` par un style CSS inline `:focus-visible` avec `box-shadow`.

---

## Problème 3 — Absence d'indicateur mode/collection dans l'interface

### Situation actuelle

L'utilisateur peut être en mode `classic`, `ghost`, `learning`, `code`, `sprint` sans aucun indicateur visuel dans la zone de frappe. Il peut avoir shufflé accidentellement vers une collection différente.

### Fix

Ajouter une ligne de contexte au-dessus de la zone de frappe affichant la collection active et le mode.

## Implémentation

### Fix 1 — `TypingArea.tsx` : i18n hint text

Ajouter en tête du composant :

```typescript
import { useTranslations } from 'next-intl';
// Dans le composant :
const t = useTranslations('typing');
```

Remplacer le texte hardcodé :

```tsx
// AVANT
<p ...>cliquer pour activer · chaque frappe produit une note</p>

// APRÈS
<p ...>{t('hint')}</p>
```

### Fix 2 — `TypingArea.tsx` : indicateur de focus accessible

Retirer `focus:outline-none` de la `className` et ajouter dans le `style` :

```tsx
style={{
  backgroundColor: 'var(--color-surface)',
  border: '1px solid var(--color-border)',
  fontFamily: 'var(--font-mono)',
  fontSize: '1.25rem',
  lineHeight: '2',
  // Focus visible accessible — WCAG 2.4.11
  // On utilise onFocus/onBlur pour gérer manuellement car Tailwind 4
  // n'expose pas facilement :focus-visible avec des CSS custom properties
}}
// + ajouter onFocus et onBlur pour le ring
```

Alternative plus propre avec Tailwind 4 — ajouter dans `globals.css` :

```css
.typing-focus-ring:focus-visible {
  box-shadow: 0 0 0 2px var(--color-accent);
  outline: none;
}
```

Puis dans `TypingArea.tsx`, remplacer `focus:outline-none` par `typing-focus-ring`.

### Fix 3 — `TypingArea.tsx` : indicateur mode/collection

**Ajouter les props au composant** (déjà présentes ? vérifier) :

- `collectionId?: string` — déjà dans les props
- `mode?: TypingMode` — déjà dans les props

**Ajouter au-dessus de la zone de frappe** (dans le div flex wrapper) :

```tsx
{
  /* Indicateur de contexte */
}
{
  (mode !== 'classic' || collectionId) && (
    <div
      style={{
        display: 'flex',
        gap: '8px',
        alignItems: 'center',
        fontFamily: 'var(--font-ui)',
        fontSize: '0.75rem',
        color: 'var(--color-text-muted)',
      }}
      aria-label={t('contextIndicatorLabel')}
    >
      {collectionId && <span>{t(`collection.${collectionId}`)}</span>}
      {collectionId && mode !== 'classic' && <span aria-hidden="true">·</span>}
      {mode !== 'classic' && (
        <span style={{ color: 'var(--color-accent)' }}>
          {t(`mode.${mode}`)}
        </span>
      )}
    </div>
  );
}
```

### Fix 4 — `transparence/page.tsx` : date dynamique

Option A (recommandée) — `force-dynamic` pour régénérer à chaque requête :

```typescript
export const dynamic = 'force-dynamic';
```

Option B — Remplacer par une date de mise à jour manuelle si le contenu change rarement :

```typescript
const LAST_UPDATED = 'mars 2026'; // ← mettre à jour manuellement
```

**Choisir l'Option A** : `force-dynamic` garantit que la date est toujours correcte.
